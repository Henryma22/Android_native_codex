# Android Codex 当前项目路线与执行约定

确认日期：2026-09-26。状态：用户已确认的目标路线；不代表以下功能已经实现或通过验收。

总体 Goal 的独立固化版本见 PROJECT_GOAL.md。本文件负责详细架构路线，Goal 文件负责给后续工程提供稳定的目标摘要和执行边界。

本文件是当前 Android Codex 的架构和实施依据。它替代旧文档中冲突的 native-first、PRoot 仅作 fallback、Root 只读 broker、强制自定义 SELinux 域、固定 capability/group 门禁、永久禁止 boot 修改等要求。历史代码与测试是现状证据，不是继续沿用旧设计的理由。用户后续明确指令优先。

执行层纪律见 [`ENGINEERING_EXECUTION_POLICY.md`](ENGINEERING_EXECUTION_POLICY.md)。后续工程必须同时遵守本文件的路线和该文件的“功能优先、风险不阻断、定向验证”原则。

## 核心目标与工程原则

让用户用自然语言完成 rooted Android 上原本繁琐的操作，例如替换字体、修改应用内部配置、安装依赖、诊断系统。产品是手机本地独立运行的 Codex，PC/远程 Bridge 不属于本项目运行链路。

**功能完整、功能可用和快速实现是不可由 Agent 擅自改变的核心原则。** 遇到问题先定位并恢复功能，结合具体操作评估风险；不能仅因为“有风险”便取消功能、缩减权限或把整个运行环境挡住。在功能实现的基础上，采用现实可行、代价相称的保护。

本项目按个人 hobbyist 工程推进，不引入企业级治理、冗余审批、通用安全 broker 或为了假想风险增加的硬门禁。这里强调的专项安全目标是避免破坏手机启动能力、造成变砖及其关联的不可恢复损失；普通应用配置出错不成为新增全局限制的理由。这不授权 Agent 执行用户任务范围以外的数据删除或泄露凭据。

“不让手机变砖”是结果目标。采用软路由意味着依赖 Agent 遵守规范、具体操作验证和用户授权，不能宣称数学意义或内核强制意义上的零风险保证。风险严重程度与发生概率必须分别评估，不虚构概率，不把“拥有写权限”等同于“将要破坏系统”。

## Goal 固化与后续判断顺序

本文件绑定当前 Android Codex 总体 Goal，是后续实现、取舍和复盘的唯一总体路线入口。Goal 的交付方向固定为：

1. 先让本地 Root runtime、官方 CLI/app-server、工具链和真实 session 可用；
2. 再补齐 CC Pocket 的 workspace/session 交互和所有已暴露功能的真实后端闭环；
3. 最后完善第三方 provider、动态能力发现、CLI/rootfs/APK 独立更新以及 Android 集成。

遇到缺陷时必须按“实际故障 → 恢复功能 → 评估具体风险 → 加入不妨碍功能的保护 → 定向验证”的顺序处理。功能完整、可用和快速实现是不可被 Agent 擅自降低的硬性目标；风险评估用于选择实现方式和保护措施，不用于把尚未实现的功能永久删掉、把正常 Root runtime 变成演示版，或用泛化审批阻断工作流。除非用户明确改变路线，否则完成一个局部检查点后继续推进总体 Goal，不把局部完成当作项目完成。

## 固定实现链路与组件职责

```text
CC Pocket 前端与 session 交互（适配 Android Codex）
    → 手机本地 runtime 启动与生命周期管理
    → KernelSU 提供的正常 Root 环境（可选择非 Root）
    → PRoot Linux ARM64 用户空间
    → 官方 Codex CLI / app-server
    → 官方 OpenAI 或用户启用的第三方模型
```

### 前端与 session

- 复用 CC Pocket 的信息架构、交互逻辑和状态管理，而非只借图标或视觉风格；按本项目后端能力做必要适配。
- 直接进入本地工作区，不显示多设备连接开屏；移除 Claude Code 和远程 Bridge 产品入口。
- workspace 下组织多个独立 thread；历史、草稿和上下文隔离，进入旧 thread 自动加载；切换页面不终止运行，多个 thread 可并行工作。
- 接好 composer、停止/重发、流式输出、tool call、approval、diff、图片、计划模式、模型/effort 和权限模式。控件必须产生真实后端效果；不可用时明确原因，不能保留无响应的假功能。
- 用量与上下文进度放在会话中；设置集中管理登录、provider、runtime、更新、主题和语言。汉化覆盖真实使用路径。

### Codex 与运行环境

- 主路线使用官方 Linux ARM64 Codex/app-server，在手机本地 Root PRoot 中运行；不要求每次上游更新都重新编译 Android ABI Codex。
- git、node、npm、npx、python 等由 Linux ARM64 Debian guest 及其包管理器提供，支持 Codex 在任务中安装依赖。Android/Bionic 开发工具包不再作为并行路径维护；Android 宿主命令直接使用系统自带工具。
- 使用 KernelSU 当前实际可用的 Root 环境；当前设计沿用正常 `ksu` 路径，不强制 `codex_agent`。不新增能力裁剪、固定组清单或“危险路径必须不可写”启动门禁。
- 区分真实内核 UID 与 PRoot 伪装身份；验证 Root 能力应看实际 worker 及真实文件操作，不能仅凭 guest 的 whoami。
- 保留轻量本地启动、停止、事件传输和更新管理；不以通用特权 broker 接管所有命令，不修改 Codex 核心来绑定私有权限协议。

### 文件可见度与宿主命令

- 显式提供 Android 宿主完整根目录视图（例如 guest 的 `/android`），不加敏感目录读取黑名单；实际读取受设备自身 Root/SELinux 能力影响，不能承诺超越设备内核权限。
- 清楚区分 Linux guest 的 `/` 与 Android 宿主的 `/`，路径映射不能让 Agent 误改另一环境。
- Android 的 pm、settings、dumpsys 等通过真实 Android 宿主执行环境调用；用最薄的环境衔接解决兼容问题，不要求 Linux guest 命令冒充宿主命令。

### 权限与 boot 软路由

- Root 是日常默认模式，提供非 Root 选择；正常 Root 命令不逐条审批，打开设置不应反复请求 Root。
- 通过运行时可读的 AGENTS.md/操作说明规范 Agent：日常读取、普通文件写入、应用配置修改和依赖安装直接进行。
- 对具体涉及启动链、启动分区、关键启动配置的修改，先识别实际目标和影响，确认适用镜像/设备/slot 及现实恢复办法，向用户说明具体操作并取得批准。批准后允许实施，不永久封锁合法功能。
- 系统文件修改能通过可撤销 KernelSU 模块实现时优先模块；模块不保证绝对安全，也不能替代所有 boot 修改。实际需要修改 boot 时保留明确授权后的直接实现路径。
- 软路由指行为规范和按任务选择操作方式，不意味着新增解析所有 shell 命令的安全中间件。不能承诺 AGENTS.md 会强制拦截所有危险命令。
- KernelSU Profile、组、capabilities、SELinux 设置由用户操作；Agent 说明具体需求，不自行修改。未知风险先给出证据和可行方案，不能擅自牺牲整体功能。

### 模型、认证与独立升级

- 支持官方 OpenAI 登录路径，以及用户配置的第三方 provider（地址、API key、模型）；按 Codex 原生配置机制接入。
- 启用第三方时，该运行实例的请求使用第三方路径，不同时走 OpenAI auth；允许保留官方登录凭据以便切回，切换需明确现有会话如何生效。
- 以安装的 CLI 实际支持的协议为准；“OpenAI 兼容”不等于所有接口完全兼容，遇到协议差异应解决适配或明确具体缺口，不能假称已支持。
- CLI、Linux rootfs/依赖与 APK 独立管理。应用内下载官方兼容 artifact、校验、切换并保留可回退版本；不在运行中强换活跃 worker 使用的文件。
- 优先使用官方 app-server 协议和能力探测，模型列表动态获取，不硬编码旧版本模型；不支持的新字段/功能应局部提示，不能连带使整个客户端失效。

## 后续实施顺序与验收

1. 恢复正常 Root 启动和基础工具可用性：去除当前不合路线的自定义域与写拒绝门禁，验证真实 worker、宿主可见度、guest 工具、宿主命令和真实 turn。
2. 完成 UI 与后端行为闭环：独立并发 thread、历史、停止/重发、设置、provider、图片、计划/权限模式等逐项以真实行为验收；保留已验证能力，不为换架构重做前端。
3. 完成独立更新、协议兼容及 Android 操作说明，验证更新后的真实会话和依赖使用；补齐仍存在的产品缺口。

每步只运行能回答具体工程问题的定向测试、构建和必要设备验证；不要每修一个点就重复长时间全量编译。真机连接时优先真机，断开时可用模拟器，但不能把模拟器结果称为真机 Root 验收。记录改动、结果和剩余缺口即可，不建立冗长审批制度。阶段通过后继续已授权的下一阶段，遇到范围外问题记入 backlog。

路线变更由用户决定。Agent 可以提出带证据的建议，不能悄悄引入新架构、安全目标或权限门槛。模型约定只作用于明确指定的对象：手机 App 内的 Codex 默认保持用户指定的 Luna low；独立开发对话遵循用户对该对话单独指定的模型/档位（当前用户指定 GPT-6 Luna Max），不得把手机端限制外推到开发对话，也不得擅自更改手机端设置。
